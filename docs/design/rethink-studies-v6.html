C · First rep

The board answers when the interviewer does.

Same turn model as InterviewView today: you draft, you send, the interviewer replies. The difference is that the reply carries board updates. Decisions made in your absence · review

What I chose, and the one I didn't.

Diagram in the rep

Built from your answer. Blank board; components appear as you name them; the interviewer crosses the failure; the fix is pinned. Pre-drawn diagrams move to the opening and to After. Reason: showing the architecture first removes the hardest part of the interview and contradicts the positioning.

Home

Stripped. Day, question, start, one Bit line. Dots, counts, fix notes and the new board library moved to Memory. Reason: the vision bans decorative dashboards; Home's job is to start a rep.

Opening

Two beats. Bit, then the diagram breaking with the positioning line and the CTA already visible. Date question moved to after the first rep. Reason: §16's "one real rep in two questions" was being violated by a 23-second story plus three setup screens.

Questions without a schematic

Blank board, and that's fine. The rep works as text on ruled lines; the board is a bonus when the model can map components. Generation from the question is the long-term path and needs validation before anyone depends on it.

Chrome

Mono caps labels removed from screens; mono survives only inside schematics. Amber deepened to #C9860A for labels on paper. Every screen is ≤ 35 words of chrome.

Bit

Opening only. Removed from Home, setup, voice and After; the vision already said Bit stays around practice, never in it, and a mascot on a working screen reads as a toy. Status lines are plain text. If it comes back anywhere, it's when feedback arrives, and small.

Relation to the code

The rep screen is today's InterviewView document (Interviewer row → your reply → Interviewer row, collapsing sent answers, clarifications behind a hairline) with the Original question card removed when an opener exists, and the board added above. Home, Setup, Voice room and Welcome are redesigns of HomeView, SetupView, InterviewVoiceRoom, WelcomeView. The board needs interview turn results to carry ops (reveal, fail, note): an API contract change and a Canvas renderer; everything else is view work.

Not decided: the system-UI rule

AGENTS.md mandates system fonts and controls. This study uses Libron, a drafting board, a custom dial and Canvas drawings. I did not edit the rule. Proposed wording if you agree: "Libron for reading, system controls where the system has one, the board as the only custom surface." If you'd rather keep the rule, the dial becomes a segmented control and type becomes SF; the board stays.

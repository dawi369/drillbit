Where you actually do the work

The reply field stays exactly as it is today; only the main question gets the inset key-facts block. Everything you act with sits below the perforation: a labelled Voice button and Send. Guided keeps its step path and choices, Mock its clock.

What to judge

  1. Which one would you want to open every morning for a month?
  2. Does Done read as finished, or as leftovers?
  3. Does the no-quote Done look intended, or like something is missing?
  4. Does it still read at a glance in light appearance?
  5. Is the single yellow on each card in the right place?

Known tradeoffs

  • Ticket: the notches and perforation are custom geometry; cheap as a SwiftUI Shape, but they must stay subtle.
  • Title block: the densest; mono labels everywhere risk reading as a costume.
  • Index card: the brightest surface in dark appearance; the deck behind it only makes sense if Recall is prominent.

Not in this board

  • Onboarding and setup. They reuse the chosen card later.
  • Native motion, Dynamic Type and VoiceOver. Those are step 2.
  • Real data. Every string is a fixture in the app’s voice.

Opens without a server; no network calls. Motion here is a CSS approximation (View Transitions where the browser supports them). Previous study: Mirage.

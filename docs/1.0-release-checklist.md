# Drillbit 1.0 lock checklist

Scope: native iOS system-design practice, complete text interviews, optional live voice, three teaching modes, saved history/feedback, personalization and daily reminders. Freeze new features while the following gates are closed. Internal builds currently use 2.0.0; choose the public version deliberately before App Store submission rather than silently renumbering TestFlight.

## Remaining release gates

Broad gates below remain open where only part has been tested. Completed implementation/simulator evidence is checked separately; this is not a new test run on Xcode 27.

- [ ] **Real-device interview loop:** on iPhone 15, prepare → text → voice → text → finish → review → relaunch. Draft, transcript, reading/disclosure state and completion must remain intact.
- [ ] **Voice personality:** verify actual audible delivery on the phone, including a newly saved local preference, a fresh voice session, technical delegation, and an explicit request to stop the character. Provider payload tests and text-form voice evaluation are not acoustic acceptance.
- [ ] **Feedback quality:** review a small fixed suite across all levels and modes: grounded corrections, appropriate help, no invented requirements or mastery claims, useful next practice. Pirate/custom tone must not change question wording or grading.
- [ ] **Navigation/accessibility:** all new screens at largest Dynamic Type, light/dark/System appearance, VoiceOver, reduced motion/transparency, keyboard shown/hidden and long content. Actions remain reachable and labels truthful.
- [ ] **Distribution:** processed TestFlight build installed on the phone; required purpose strings, privacy declarations, support/privacy links, review account and store metadata checked against actual behavior.

## Completed checks (recorded evidence, 13 September 2026)

- [x] **Backend regression suite:** 100 API/D1 tests passed, including personalization scoping, voice-start profile pinning, 30-session history, account isolation/deletion and legacy-client compatibility.
- [x] **Native core regression suite:** 32 core Swift tests passed. Recent simulator journeys cover settings/profile editing, immediate theme changes, voice/text draft preservation and Home preparation.
- [x] **Initial personality evaluation:** live Gemini text/delegated-response samples show preferences and explicit overrides being followed. Some responses remain too verbose; actual spoken character consistency remains a phone gate.
- [x] **Local-first settings implementation and simulator recovery:** settings are durable locally before dismissing; background sync and revision-specific acknowledgements preserve newer choices.

Evidence: `acceptance.md`, `interviewer-personalization.md` and `product-completeness.md`. Xcode 27 rerun: 32 native core tests pass and Release archive 2.0.0 (6) succeeds; internal TestFlight upload succeeded; Apple processing/tester availability remains to be verified. Earlier simulator evidence predates Xcode 27.

## Owner decisions — 13 September 2026

- **Audio interruptions — code review completed; physical tests waived by owner.** Session loss/background stops audio; restoration never starts recording; disconnects require explicit recovery. Registered interruption/route observers before audio activation and release audio before failed-start network recovery. Xcode 27 Release archive succeeds; 32 native core tests pass.
- **Failure recovery — code review completed; physical scenarios waived by owner.** Durable pending commands, stable retry IDs, revision conflicts, single-flight submission, account guards and compare-and-clear settings acknowledgements are present. API/D1 regression suite passes 100 tests; no claim of new physical-device verification.
- **Account/data lifecycle — deferred by owner:** export, deletion, reset and account-switching release checks. Existing evidence remains in acceptance records; no new verification claimed.
- **Operations — deferred by owner:** crash visibility, budgets, backup restoration and rollback release checks. Deferral is not a passing test result.

## After the freeze

Ship fixes to the gates above, not new surfaces. Defer Android, extra model/provider choices, readiness scores, inferred personal biography, elaborate theme systems, new social/gamification loops and a larger home dashboard. A materialized history cache should be driven by measured latency, not added speculatively.

## Exit criterion

One known build passes the phone checklist and fixed response-quality suite; no known work-loss, recording-lifecycle, account-isolation or misleading-feedback blockers remain. Record build IDs, observed evidence and remaining low-severity issues. Passing CI alone is not release approval.
